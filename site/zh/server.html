为实验室部署

一个实验室，一个数据库。

BioManager 的部署步骤。选一种方式，按顺序做完每一步，看到完成标志就好了。 大多数实验室一分钱都不用花。

第一部分

从这里开始

选择方案

  1. 有几个人用？只有你自己：A。不止一个人：看第 2 题。
  2. 需要在实验室网络以外使用吗？（在家里、用手机流量、在别的院区。连学校 VPN 算在网络以内。） 需要：D；如果有人装不了 Tailscale 应用，选 E。不需要：看第 3 题。
  3. 学校 IT 部门能给你一台服务器吗？能：C。不能：B。
方式谁能访问每月费用设置时间
A · 单台电脑只有这台电脑$02 分钟
B · 实验室里的 Linux 电脑实验室或校园网络，以及它的 VPN有闲置电脑就是 $0（新买一台小主机，一次性 $300–600）1 小时
C · 学校的服务器校园网络和 VPN通常 $0；有些 IT 部门收费取决于 IT 部门，之后 30 分钟
D · 云服务器 + Tailscale 推荐你的实验室，在哪里都能访问；其他人都不能$0（Oracle Cloud Always Free + Tailscale 免费套餐），付费服务器大约 $5–71 小时
E · 云服务器 + 自己的域名任何知道网址的人（仍需账号才能登录）同 D，另加域名大约 $1（每年 $10–15）1–2 小时

价格是这些服务在 2026 年 9 月的收费，注册前请再核实。所有服务器方式（B–E）都包含每晚备份、 每周恢复测试和 HTTPS。

也可以让桌面版来做在桌面版里，设置 → 搭建实验室服务器可以替你完成 B、C、D 或 E； 在 Mac 上，它还能把这台 Mac 设成全实验室用的服务器。每一步执行前都会先给你看，也可以把你的记录一起带过去。

让 AI 助手来设置

能使用终端的 AI 助手（Claude Code、Cursor、Codex 等）可以按 deploy-with-ai.md（本页专门写给它的版本）替你完成 B、C、D 或 E。 把下面这段话粘贴给你的助手：

请阅读 https://biomanager.org/deploy-with-ai.md 并按照它为我的实验室搭建一台 BioManager 服务器。先问我其中列出的问题，推荐一种方案，在创建任何需要花钱或把服务器开放到互联网的东西之前，先等我同意。不要让我把密码或密钥粘贴到这个对话里：告诉我该在哪里自己输入。

注册账号、批准登录、输入每一个密码，仍然由你自己来做；指南会让助手在这些地方停下来问你。

第二部分

部署方式

A · 单台电脑：桌面版

一个人用$02 分钟

你需要

  • 一台 Mac（Apple 芯片或 Intel）、Windows 电脑或 Linux 电脑（x86-64）。
  • 费用：每月 $0。
  • 时间：2 分钟。

  1. 在下载页面下载适合你电脑的文件。

    你应该看到：“下载”文件夹里有 BioManager-macOS-AppleSilicon.zip、 BioManager-macOS-Intel.zip、BioManager-Windows.zip 或 BioManager-Linux.AppImage。

    如果不是：Mac 上，苹果菜单 → 关于本机会显示你的芯片类型。

  2. 打开它。

    Mac：解压，把 BioManager 拖进“应用程序”，然后右键点按它 → 打开 → 打开。 Windows：解压 zip，打开 BioManager.exe，出现警告时选更多信息 → 仍要运行。 Linux：

    cd ~/Downloads && chmod +x BioManager-Linux.AppImage && ./BioManager-Linux.AppImage

    你应该看到：BioManager 窗口打开，请你创建账号。

    如果不是：Mac 只给出移到废纸篓：打开系统设置 → 隐私与安全性 → 仍要打开。 Linux 上 AppImage 打不开，是缺少 FUSE：安装 libfuse2。

  3. 创建你的账号，回答设置问题（用户指南）。

    你应该看到：BioManager 的首页，上面是你勾选的数据库。

完成标志：BioManager 打开在首页，并且你已登录。

千万不要把数据文件夹放进 Dropbox、OneDrive、Google Drive 或 iCloud Drive同步会损坏数据库。 数据在 ~/Library/Application Support/Biomanager/（Mac）、%APPDATA%\Biomanager\（Windows） 或 ~/.local/share/Biomanager/（Linux）：用 Time Machine 或“文件历史记录”备份这个文件夹。

同一个可信网络里的几个人，不用服务器也能共用这台电脑上的实验室：设置 → 设备 → 在网络上共享这个实验室。 它没有每晚备份，连接也不加密（设备）。

B · 实验室里的一台 Linux 电脑

实验室局域网有闲置电脑就是 $01 小时

你需要

  • 一台一直开着的 Linux 电脑（Ubuntu 24.04，或其他带 systemd 的 Linux），x86-64 或 ARM，至少 2 个 CPU 核心、 2 GB 内存、20 GB 空闲硬盘。如果是 Mac，请用桌面版：设置 → 搭建实验室服务器 → 这台电脑，供全实验室使用。
  • 这台电脑上一个能用 sudo 的账号。
  • IT 部门给它的固定 IP 地址或 DNS 名称。
  • 费用：每月 $0。
  • 时间：大约一小时。

  1. 向 IT 部门申请这台电脑的固定 IP 地址或 DNS 名称，并关闭睡眠（Ubuntu：设置 → 电源 → 自动挂起 → 关闭）。 然后查看它的地址：

    hostname -I

    你应该看到：列出的地址里有 IT 部门给你的那个 IP。

    如果不是：重启后地址会变：请 IT 部门为这台电脑做 DHCP 地址保留。

  2. 安装 Docker。

    curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER

    你应该看到：Docker 安装程序运行结束，没有报错。

    如果不是：出现 sudo: a password is required 或 not in the sudoers file： 换一个能用 sudo 的账号，或者找 IT 部门。

  3. 退出登录，重新登录，然后检查 Docker。

    docker compose version

    你应该看到：Docker Compose version v…

    如果不是：出现 permission denied while trying to connect to the Docker daemon socket： 第 2 步之后你还没有重新登录。退出再登录（或重启）。

  4. 下载 BioManager。

    sudo mkdir -p /opt/biomanager && sudo chown "$USER" /opt/biomanager
curl -fsSL -o /tmp/biomanager-server.tar.gz \
  https://github.com/gaspolymerase/biomanager/releases/latest/download/biomanager-server.tar.gz
tar -xzf /tmp/biomanager-server.tar.gz -C /opt/biomanager
/opt/biomanager/Biomanager/deploy/host/load-image.sh

    你应该看到：Downloading BioManager <version> for amd64…（或 arm64），然后是 Loaded image: ghcr.io/gaspolymerase/biomanager:<version> 和 Loaded. Start or update with: …

    如果不是：No BioManager image for …：BioManager 只支持 x86-64 和 ARM64。 Could not download：这台电脑连不上 github.com；问问 IT 部门是否要设代理，然后重新运行最后一行。

  5. 写入不需要你选择的设置：数据库密码、证书类型和备份文件夹。

    cd /opt/biomanager/Biomanager/deploy
cp .env.example .env && chmod 600 .env
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -hex 24)|" .env
sed -i "s|^TLS=.*|TLS=internal|; s|^BACKUP_DIR=.*|BACKUP_DIR=/opt/biomanager/backups|" .env

    你应该看到：没有任何输出。

    如果不是：cannot stat '.env.example'：第 4 步没有解压成功。重做第 4 步。

  6. 填入你的地址和时区。打开设置文件：

    nano .env

    把这两行改成下面这样，按 Ctrl+O、Enter 保存，按 Ctrl+X 退出：

    DOMAIN=<your-domain>
TZ=<your-time-zone>

    <your-domain>：第 1 步的固定 IP 地址或 DNS 名称，不带 https://。 <your-time-zone>：例如 Asia/Shanghai 或 Europe/Berlin； timedatectl 会显示这台电脑的时区。如果有第二块硬盘，也把 BACKUP_DIR 改成那块硬盘上的文件夹。

    你应该看到：DOMAIN= 在文件开头附近，TZ= 在中间。

    如果不是：nano: command not found：运行 sudo apt-get install nano。

  7. 检查设置。

    grep -E '^(DOMAIN|TLS|TZ|BACKUP_DIR)=' .env
docker compose config --quiet && echo "settings ok"

    你应该看到：你的四行设置，其中 TLS=internal，然后是 settings ok。

    如果不是：set POSTGRES_PASSWORD in .env：重做第 5 步。仍是 DOMAIN=biomanager.example.edu：修改没有保存，重做第 6 步。

  8. 启动 BioManager。

    docker compose up -d --build

    你应该看到：一两分钟后，biomanager-db-1、biomanager-app-1、 biomanager-caddy-1 和 biomanager-backup-1 都显示 Started 或 Healthy。

    如果不是：pull access denied for ghcr.io/gaspolymerase/biomanager：先运行 host/load-image.sh，再运行这一步。container biomanager-app-1 is unhealthy： docker compose logs --tail 100 app 会说明原因。

  9. 检查所有服务都在运行。

    docker compose ps

    你应该看到：db 和 app 显示 (healthy)，caddy 显示 Up，backup 显示 (healthy)；它做第一次备份的几分钟里会显示 (health: starting)。

    如果不是：少了某个服务，或显示 Restarting：运行 docker compose logs --tail 100 <service>。

  10. 取得创建第一个账号用的设置码。

    docker compose logs app | grep "setup code"

    你应该看到：No accounts yet. Create the first admin at /register with setup code 1a2b-3c4d-5e6f (also saved in /data/setup-code).

    如果不是：什么都没有：应用还在启动。等一分钟再试，或运行 docker compose exec app cat /data/setup-code。

  11. 导出 BioManager 的证书，给实验室的设备信任。

    docker compose exec caddy cat /data/caddy/pki/authorities/local/root.crt > biomanager-root.crt
head -1 biomanager-root.crt

    你应该看到：-----BEGIN CERTIFICATE-----

    如果不是：No such file or directory：Caddy 还在启动。等十秒再试。

  12. 在每台要打开 BioManager 的电脑和手机上做一次：把 biomanager-root.crt 传过去（邮件、U 盘、隔空投送）， 然后安装它。

    • Mac：双击它；在“钥匙串访问”里打开它，把信任 → 使用此证书时 → 始终信任选上。
    • Windows：双击它 → 安装证书 → 本地计算机 → 将所有的证书都放入下列存储 → 受信任的根证书颁发机构。
    • iPhone、iPad：打开它，在设置 → 通用 → VPN与设备管理里安装描述文件，然后在 设置 → 通用 → 关于本机 → 证书信任设置里打开它。
    • Android：设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书。

    你应该看到：在这台设备上打开 https://<your-domain>，没有证书警告。

    如果不是：iPhone 上证书信任设置里的开关还没打开。Firefox 用自己的证书列表： 设置 → 隐私与安全 → 查看证书 → 证书颁发机构 → 导入。

  13. 在其中一台设备上打开 https://<your-domain>/register，填写名称、用户名、密码和第 10 步的 设置码，然后点创建账号。第一个账号就是实验室的管理员。

    你应该看到：你已登录，实验室设置问卷打开了。

    如果不是：提示设置码不对：从第 10 步重新复制，三组字符和中间的短横线都要。

  14. 打开告警、看门狗和每周自动更新。

    sudo host/install.sh

    你应该看到：Installed. Alerts go to ntfy topic: biomanager-…，以及两个定时器 biomanager-watchdog.timer 和 biomanager-maintenance.timer。在手机上的 ntfy 应用里订阅这个主题。

    如果不是：command not found：你不在 deploy 文件夹里。先运行 cd /opt/biomanager/Biomanager/deploy。

完成标志：在实验室网络里的另一台电脑上，https://<your-domain>/healthz 显示 ok，没有证书警告；并且能以管理员身份登录 https://<your-domain>。

实验室的数据和备份都在同一台电脑上它的硬盘一坏，两样都没了。把 BACKUP_DIR 放到第二块硬盘上，并打开异地备份（见运行之后）。

C · 学校或院系的服务器

校园网络和 VPN通常 $0等 IT，之后 30 分钟

你需要

  • IT 部门给的一台 Linux 虚拟机，以及上面一个能用 sudo 的账号（第 1 步一起申请）。
  • IT 部门为它的名称签发的证书：一个证书文件和它的私钥文件。
  • 你自己的电脑，连着校园网络或 VPN，能打开终端。
  • 费用：通常每月 $0；有些 IT 部门收费。
  • 时间：等 IT 部门处理，之后 30 分钟。

  1. 把这段申请发给 IT 部门（他们多半要英文的话可以直接用）。

    We'd like a small Linux VM (Ubuntu 24.04, 2 vCPU, 4 GB RAM, 40 GB disk) with Docker and its compose plugin, a DNS name such as biomanager.ourdept.example.edu, a TLS certificate for that name, and port 443 open to the campus network and VPN. It runs BioManager, a lab database, in Docker containers. Please give me an account on it that can use sudo.

    你应该看到：IT 部门回复 DNS 名称、登录方式和证书：一个 .crt 或 .pem 文件和它的私钥。

    如果不是：IT 部门签发不了证书：第 6 步里用 TLS=internal 代替 files， 跳过第 5 步，启动后再做 B 的第 11、12 步。

  2. 在你的电脑上，把 IT 部门给的两个证书文件复制到虚拟机。

    scp <certificate-file> <key-file> <you>@<your-domain>:

    <certificate-file>、<key-file>：IT 部门给的文件（第 5 步只写文件名）。 <you>：你在虚拟机上的账号。<your-domain>：虚拟机的 DNS 名称。

    你应该看到：两个文件都复制到 100%。

    如果不是：Connection timed out：你不在校园网络里。先连上 VPN。

  3. 登录虚拟机，检查 Docker。

    ssh <you>@<your-domain>
    docker compose version

    你应该看到：Docker Compose version v…

    如果不是：permission denied while trying to connect to the Docker daemon socket： 运行 sudo usermod -aG docker $USER，退出再登录。docker: command not found：请 IT 部门安装 Docker。

  4. 下载 BioManager。

    sudo mkdir -p /opt/biomanager && sudo chown "$USER" /opt/biomanager
curl -fsSL -o /tmp/biomanager-server.tar.gz \
  https://github.com/gaspolymerase/biomanager/releases/latest/download/biomanager-server.tar.gz
tar -xzf /tmp/biomanager-server.tar.gz -C /opt/biomanager
/opt/biomanager/Biomanager/deploy/host/load-image.sh

    你应该看到：Loaded image: ghcr.io/gaspolymerase/biomanager:<version> 和 Loaded. Start or update with: …

    如果不是：Could not download：虚拟机连不上 github.com。问问 IT 部门是否要设代理， 然后重新运行最后一行。

  5. 把证书放到 BioManager 读取的位置。

    cp ~/<certificate-file> /opt/biomanager/Biomanager/deploy/certs/server.crt
cp ~/<key-file> /opt/biomanager/Biomanager/deploy/certs/server.key
ls /opt/biomanager/Biomanager/deploy/certs

    你应该看到：server.crt server.key

    如果不是：No such file：用 ls ~ 核对文件名。

  6. 写入不需要你选择的设置。

    cd /opt/biomanager/Biomanager/deploy
cp .env.example .env && chmod 600 .env
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -hex 24)|" .env
sed -i "s|^TLS=.*|TLS=files|; s|^BACKUP_DIR=.*|BACKUP_DIR=/opt/biomanager/backups|" .env

    你应该看到：没有任何输出。

  7. 填入你的地址和时区：打开文件，改这两行，按 Ctrl+O、Enter 保存， 按 Ctrl+X 退出。

    nano .env
    DOMAIN=<your-domain>
TZ=<your-time-zone>

    <your-domain>：IT 部门给的 DNS 名称，不带 https://。 <your-time-zone>：例如 Asia/Shanghai 或 Europe/Berlin。

    你应该看到：DOMAIN= 在开头附近，TZ= 在中间。

  8. 检查设置。

    grep -E '^(DOMAIN|TLS|TZ|BACKUP_DIR)=' .env
docker compose config --quiet && echo "settings ok"

    你应该看到：你的四行设置，其中 TLS=files，然后是 settings ok。

    如果不是：set POSTGRES_PASSWORD in .env：重做第 6 步。仍是 DOMAIN=biomanager.example.edu：修改没有保存，重做第 7 步。

  9. 启动 BioManager。

    docker compose up -d --build

    你应该看到：biomanager-db-1、biomanager-app-1、 biomanager-caddy-1 和 biomanager-backup-1 都显示 Started 或 Healthy。

    如果不是：pull access denied：先运行 host/load-image.sh，再运行这一步。

  10. 检查所有服务都在运行。

    docker compose ps

    你应该看到：db 和 app 显示 (healthy)，caddy 显示 Up，backup 显示 (healthy)，最初几分钟可能是 (health: starting)。

    如果不是：caddy 不断重启：运行 docker compose logs caddy；通常是私钥和证书 不配套，或两个文件放反了。

  11. 取得创建第一个账号用的设置码。

    docker compose logs app | grep "setup code"

    你应该看到：No accounts yet. Create the first admin at /register with setup code 1a2b-3c4d-5e6f …

    如果不是：什么都没有：等一分钟再试。

  12. 在你的电脑上打开 https://<your-domain>/register，填写名称、用户名、密码和设置码， 然后点创建账号。第一个账号就是实验室的管理员。

    你应该看到：你已登录，实验室设置问卷打开了。

    如果不是：部分设备提示证书警告：向 IT 部门要包含完整证书链的证书，重新放进 server.crt，然后运行 docker compose restart caddy。

  13. 打开告警、看门狗和每周自动更新。

    sudo host/install.sh

    你应该看到：Installed. Alerts go to ntfy topic: biomanager-…。在 ntfy 应用里订阅它。

    如果不是：command not found：先运行 cd /opt/biomanager/Biomanager/deploy。

完成标志：在校园网络或 VPN 里的电脑上，https://<your-domain>/healthz 显示 ok，没有证书警告；并且能以管理员身份登录。

D · 配合 Tailscale 的云服务器 推荐

实验室成员，在哪里都能用$01 小时

服务器在互联网上没有任何开放端口。实验室成员打开 Tailscale 应用，就能在任何网络下用 https://biomanager.tail1234.ts.net（换成你自己的 tailnet 名称）打开它。

你需要

  • 一个 Oracle Cloud 账号。注册时会要求绑定银行卡验证身份； Always Free 资源永远不收费。主区域（home region）要选好：选定后不能更改。（也可以用任何服务商的、带 cloud-init 输入框的 Ubuntu 24.04 云服务器：Hetzner 大约每月 €4，DigitalOcean 或 AWS Lightsail 大约每月 $5–7。）
  • 一个 Tailscale 账号（最多 6 个用户免费；其他人可以用自己的 免费账号，你把服务器共享给他们）。
  • 你自己的电脑，能打开终端，并装好 Tailscale 应用。
  • 费用：用 Oracle Always Free 每月 $0。
  • 时间：大约一小时。

  1. 在你的电脑上生成一个 SSH 密钥。每个问题都直接按 Enter。

    ssh-keygen -t ed25519

    你应该看到：Your public key has been saved in …/.ssh/id_ed25519.pub

    如果不是：… already exists. Overwrite (y/n)?：输入 n，用你已有的密钥。

  2. 在你的电脑上下载服务器安装包，显示其中的首次启动脚本。

    curl -fsSL -o biomanager-server.tar.gz https://github.com/gaspolymerase/biomanager/releases/latest/download/biomanager-server.tar.gz
tar -xzf biomanager-server.tar.gz
cat Biomanager/deploy/cloud-init.yaml

    你应该看到：一个以 #cloud-config 开头的文件。第 3 步要把它整个粘贴进去。

    如果不是：Windows PowerShell 提示找不到参数：把 curl 换成 curl.exe。

  3. 创建服务器：Oracle Cloud 控制台 → ☰ → Compute → Instances → Create instance，设置：

    • Image：Change image → Ubuntu → Canonical Ubuntu 24.04。
    • Shape：Change shape → Ampere → VM.Standard.A1.Flex，2 OCPU、12 GB 内存。
    • Networking：新建虚拟云网络和公共子网；分配公网 IPv4 地址。
    • Add SSH keys：Upload public key files (.pub) → 第 1 步的 id_ed25519.pub。
    • Advanced options → Management → Initialization script → Paste cloud-init script：第 2 步的 cloud-init.yaml 全部内容。

    然后点 Create。

    你应该看到：几分钟内实例变成 Running，页面上有 Public IP address。记下它： 下面的 <public-ip> 就是它。

    如果不是：Out of capacity for shape VM.Standard.A1.Flex：在 Placement 里换一个可用性域，或者稍后再试。

  4. 在你的电脑上登录服务器。问到指纹时输入 yes。

    ssh ubuntu@<public-ip>

    你应该看到：以 ubuntu@ 开头的命令提示符。

    如果不是：Connection timed out：服务器还在启动，两分钟后再试。 Permission denied (publickey)：运行 ssh -i ~/.ssh/id_ed25519 ubuntu@<public-ip>。

  5. 等首次启动脚本运行完（服务器启动后 5–10 分钟）。

    test -f /var/lib/biomanager-ready && echo ready

    你应该看到：ready

    如果不是：什么都没有：还在运行。sudo tail -f /var/log/cloud-init-output.log 可以看进度（按 Ctrl+C 停止查看）。如果这个日志里始终没有 Docker，说明第 3 步没有粘贴脚本： 删除（terminate）这台服务器，重新创建。

  6. 把服务器加入你的 Tailscale 网络。

    sudo tailscale up --hostname=biomanager

    你应该看到：To authenticate, visit: https://login.tailscale.com/a/…。在你的电脑上 打开这个链接并登录；终端随后显示 Success.

    如果不是：tailscale: command not found：第 5 步还没完成。

  7. 在 Tailscale 管理控制台里：Machines → biomanager → ⋯ → Disable key expiry（关闭密钥过期）。

    你应该看到：biomanager 这一行显示 Expiry disabled。

    如果不是：它叫 biomanager-1：有一台旧机器占用了这个名字。删除旧的 （⋯ → Remove），把这台改名为 biomanager（⋯ → Edit machine name）。

  8. 在管理控制台的 DNS 页面：打开 MagicDNS，再在 HTTPS Certificates 下点 Enable HTTPS。 记下页面上的 Tailnet name，类似 tail1234.ts.net。

    你应该看到：两项都已打开。服务器的地址就是 biomanager. 加上你的 tailnet 名称： 下面的 <your-domain> 就是它。

    如果不是：没有 HTTPS 选项：先打开 MagicDNS。

  9. 在你的电脑上打开 Tailscale 应用，用同一个账号登录。在服务器窗口里输入 exit，再通过 Tailscale 重新登录。

    ssh ubuntu@biomanager

    你应该看到：又出现 ubuntu@ 提示符。之后都用这个连接。

    如果不是：Could not resolve hostname biomanager：你电脑上的 Tailscale 没打开、 登录的是别的账号，或者 MagicDNS 没打开（第 8 步）。

  10. 下载 BioManager。

    curl -fsSL -o /tmp/biomanager-server.tar.gz \
  https://github.com/gaspolymerase/biomanager/releases/latest/download/biomanager-server.tar.gz
tar -xzf /tmp/biomanager-server.tar.gz -C /opt/biomanager
/opt/biomanager/Biomanager/deploy/host/load-image.sh

    你应该看到：Downloading BioManager <version> for arm64…，然后是 Loaded image: ghcr.io/gaspolymerase/biomanager:<version> 和 Loaded. Start or update with: …

    如果不是：permission denied while trying to connect to the Docker daemon socket： 输入 exit，再 ssh ubuntu@biomanager，重做这一步。Cannot mkdir: Permission denied： 运行 sudo chown ubuntu /opt/biomanager，重做这一步。

  11. 写入不需要你选择的设置：数据库密码、Tailscale 证书和备份文件夹。

    cd /opt/biomanager/Biomanager/deploy
cp .env.example .env && chmod 600 .env
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -hex 24)|" .env
sed -i "s|^TLS=.*|TLS=tailscale|; s|^#COMPOSE_FILE=|COMPOSE_FILE=|; s|^BACKUP_DIR=.*|BACKUP_DIR=/opt/biomanager/backups|" .env

    你应该看到：没有任何输出。

  12. 填入你的地址和时区：打开文件，改这两行，按 Ctrl+O、Enter 保存， 按 Ctrl+X 退出。

    nano .env
    DOMAIN=<your-domain>
TZ=<your-time-zone>

    <your-domain>：biomanager. 加上第 8 步的 tailnet 名称，例如 biomanager.tail1234.ts.net。<your-time-zone>：例如 Asia/Shanghai 或 Europe/Berlin。

    你应该看到：DOMAIN= 在开头附近，TZ= 在中间。

  13. 检查设置。

    grep -E '^(DOMAIN|TLS|COMPOSE_FILE|TZ|BACKUP_DIR)=' .env
docker compose config --quiet && echo "settings ok"

    你应该看到：DOMAIN=biomanager.tail1234.ts.net（换成你的 tailnet）、 TLS=tailscale、COMPOSE_FILE=compose.yaml:compose.tailscale.yaml、你的 TZ、 BACKUP_DIR=/opt/biomanager/backups，然后是 settings ok。

    如果不是：set POSTGRES_PASSWORD in .env 或没有 COMPOSE_FILE 这一行： 重做第 11 步。仍是 DOMAIN=biomanager.example.edu：修改没有保存，重做第 12 步。

  14. 启动 BioManager。

    docker compose up -d --build

    你应该看到：一两分钟后，biomanager-db-1、biomanager-app-1、 biomanager-caddy-1 和 biomanager-backup-1 都显示 Started 或 Healthy。

    如果不是：pull access denied for ghcr.io/gaspolymerase/biomanager：先运行 host/load-image.sh，再运行这一步。container biomanager-app-1 is unhealthy： docker compose logs --tail 100 app 会说明原因。

  15. 检查所有服务都在运行。

    docker compose ps

    你应该看到：db 和 app 显示 (healthy)，caddy 显示 Up，backup 显示 (healthy)；它做第一次备份的几分钟里会显示 (health: starting)。

    如果不是：少了某个服务，或显示 Restarting：运行 docker compose logs --tail 100 <service>。

  16. 取得创建第一个账号用的设置码。

    docker compose logs app | grep "setup code"

    你应该看到：No accounts yet. Create the first admin at /register with setup code 1a2b-3c4d-5e6f (also saved in /data/setup-code).

    如果不是：什么都没有：应用还在启动。等一分钟再试。

  17. 在打开了 Tailscale 的电脑上打开 https://<your-domain>/register，填写名称、用户名、密码和 设置码，然后点创建账号。第一个账号就是实验室的管理员。

    你应该看到：你已登录，实验室设置问卷打开了。

    如果不是：打不开或提示证书错误：Tailscale 的 HTTPS 没打开（第 8 步），或者缺少 COMPOSE_FILE 这一行（第 11 步）。改好后运行 docker compose up -d；仍不行就看 docker compose logs caddy。

  18. 打开告警、看门狗和每周自动更新。

    sudo host/install.sh

    你应该看到：Installed. Alerts go to ntfy topic: biomanager-…，以及两个定时器 biomanager-watchdog.timer 和 biomanager-maintenance.timer。在手机上的 ntfy 应用里订阅这个主题。

    如果不是：command not found：先运行 cd /opt/biomanager/Biomanager/deploy。

  19. 关闭互联网上的 SSH：Oracle Cloud 控制台 → 这台实例 → Subnet（在 Primary VNIC 下）→ Security Lists → Default Security List → Ingress Rules，勾选目标端口为 22 的规则 → Remove。 然后在你的电脑上：

    ssh -o ConnectTimeout=10 ubuntu@<public-ip>

    你应该看到：Connection timed out，而 ssh ubuntu@biomanager 仍然能用。

    如果不是：仍然能连上：还有别的规则开放了 22 端口（看看实例上的网络安全组），也删掉它。

  20. 可选，建议做：防止 Oracle 停掉服务器。Oracle Cloud 控制台 → Billing → Upgrade and Manage Payment → Upgrade to Pay As You Go（升级为按量付费）。Always Free 资源仍然免费。

    你应该看到：账号类型显示为 Pay As You Go。

    如果不做：Always Free 服务器看起来闲置一周，Oracle 会把它停掉。在 Compute → Instances 里重新启动即可，数据不会丢。

完成标志：在打开了 Tailscale 的手机或电脑上，https://<your-domain>/healthz 显示 ok；能以管理员身份登录 https://<your-domain>；并且 ssh ubuntu@<public-ip> 连接超时。

E · 用自己域名的云服务器

任何知道网址的人每月约 $11–2 小时

不用装任何应用：谁都能打开 https://biomanager.yourlab.example。登录页面在公开的互联网上，所以请使用强密码， 并考虑用 Google 或 Microsoft 登录。

你需要

  • 一个 Oracle Cloud 账号（免费；绑卡验证身份；主区域选定后不能更改）， 或任何服务商带 cloud-init 输入框的 Ubuntu 24.04 云服务器。
  • 一个域名（每年大约 $10–15），注册商要能添加 DNS 记录，例如 Cloudflare、Porkbun 或 Namecheap；或者院系给的子域名。
  • 一个邮箱地址，给签发证书的 Let's Encrypt 用。
  • 你自己的电脑，能打开终端。
  • 费用：用 Oracle Always Free，每月大约 $1（域名）。
  • 时间：1–2 小时；新的 DNS 记录最长可能要一小时才处处生效。

  1. 在你的电脑上生成一个 SSH 密钥。每个问题都直接按 Enter。

    ssh-keygen -t ed25519

    你应该看到：Your public key has been saved in …/.ssh/id_ed25519.pub

    如果不是：… already exists. Overwrite (y/n)?：输入 n，用你已有的密钥。

tar -xzf biomanager-server.tar.gz
cat Biomanager/deploy/cloud-init.yaml

    你应该看到：一个以 #cloud-config 开头的文件。第 3 步要把它整个粘贴进去。

    如果不是：Windows PowerShell 提示找不到参数：把 curl 换成 curl.exe。

  3. 创建服务器：Oracle Cloud 控制台 → ☰ → Compute → Instances → Create instance，设置：

    • Image：Change image → Ubuntu → Canonical Ubuntu 24.04。
    • Shape：Change shape → Ampere → VM.Standard.A1.Flex，2 OCPU、12 GB 内存。
    • Networking：新建虚拟云网络和公共子网；分配公网 IPv4 地址。
    • Add SSH keys：Upload public key files (.pub) → 第 1 步的 id_ed25519.pub。
    • Advanced options → Management → Initialization script → Paste cloud-init script：第 2 步的 cloud-init.yaml 全部内容。

    然后点 Create。

    你应该看到：实例变成 Running，页面上有 Public IP address：下面的 <public-ip> 就是它。

    如果不是：Out of capacity for shape VM.Standard.A1.Flex：在 Placement 里换一个可用性域，或者稍后再试。

    你应该看到：多了两行：TCP 80 和 TCP 443。Let's Encrypt 签发证书需要 80 端口。

    nslookup <your-domain>

    <your-domain>：biomanager. 加上你的域名，例如 biomanager.yourlab.example。

    你应该看到：名称下面有 Address: <public-ip>。

    如果不是：还没有地址：等 10 分钟再试。用 Cloudflare 的话，这条记录要设成 DNS only （灰色云朵），不要代理。

  6. 登录服务器。问到指纹时输入 yes。

    你应该看到：以 ubuntu@ 开头的命令提示符。

    如果不是：Connection timed out：两分钟后再试。 Permission denied (publickey)：运行 ssh -i ~/.ssh/id_ed25519 ubuntu@<public-ip>。

    test -f /var/lib/biomanager-ready && echo ready

    你应该看到：ready。然后输入 exit，重新登录（第 6 步），这样你的账号才能用 Docker。

    如果不是：什么都没有：sudo tail -f /var/log/cloud-init-output.log 可以看进度。 如果这个日志里始终没有 Docker，说明第 3 步没有粘贴脚本：删除这台服务器，重新创建。

  8. 下载 BioManager。

    curl -fsSL -o /tmp/biomanager-server.tar.gz \
  https://github.com/gaspolymerase/biomanager/releases/latest/download/biomanager-server.tar.gz
tar -xzf /tmp/biomanager-server.tar.gz -C /opt/biomanager

    你应该看到：Loaded image: ghcr.io/gaspolymerase/biomanager:<version> 和 Loaded. Start or update with: …

    如果不是：permission denied while trying to connect to the Docker daemon socket： 输入 exit，重新登录，重做这一步。

  9. 写入不需要你选择的设置。

    cd /opt/biomanager/Biomanager/deploy
cp .env.example .env && chmod 600 .env
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -hex 24)|" .env
sed -i "s|^TLS=.*|TLS=acme|; s|^BACKUP_DIR=.*|BACKUP_DIR=/opt/biomanager/backups|" .env

    你应该看到：没有任何输出。

    nano .env

ACME_EMAIL=<your-email>
TZ=<your-time-zone>

    <your-domain>：第 5 步的名称。<your-email>：证书快到期时 Let's Encrypt 会发邮件到这里。<your-time-zone>：例如 Asia/Shanghai 或 Europe/Berlin。

    你应该看到：DOMAIN= 和 ACME_EMAIL= 在开头附近，TZ= 在中间。

    你应该看到：你的五行设置，其中 TLS=acme，然后是 settings ok。

    如果不是：set POSTGRES_PASSWORD in .env：重做第 9 步。仍是 DOMAIN=biomanager.example.edu：修改没有保存，重做第 10 步。

    docker compose up -d --build

    你应该看到：biomanager-db-1、biomanager-app-1、 biomanager-caddy-1 和 biomanager-backup-1 都显示 Started 或 Healthy。

    如果不是：pull access denied：先运行 host/load-image.sh，再运行这一步。

  13. 检查 Caddy 拿到了证书。

    docker compose logs caddy | grep "certificate obtained"

    你应该看到：一行包含 certificate obtained successfully 和你的域名。

    如果不是：还没有：等一分钟再试。出现 challenge failed 或 timeout： DNS 记录（第 5 步）或 80 端口（第 4 步）还不对。改好后运行 docker compose restart caddy。

  14. 取得创建第一个账号用的设置码。

    你应该看到：No accounts yet. Create the first admin at /register with setup code 1a2b-3c4d-5e6f …

  15. 打开 https://<your-domain>/register，填写名称、用户名、密码和设置码，然后点 创建账号。第一个账号就是实验室的管理员。

    你应该看到：你已登录，实验室设置问卷打开了。

把桌面版的记录带过来

记录、历史和编号都会一起带过来。要在新服务器第一次启动之前做：在 B、C、D 或 E 里做完检查设置那一步后， 用下面的步骤代替后面的步骤，一直到打开告警那一步。之后用你原来的账号登录，不需要设置码。

  1. 退出桌面版。然后在那台电脑上，把它的数据库和上传的文件复制到服务器。

    scp "$HOME/Library/Application Support/Biomanager/data/biomanager.db" <you>@<server>:/tmp/lab.db
scp -r "$HOME/Library/Application Support/Biomanager/uploads" <you>@<server>:/tmp/lab-uploads

    这是 Mac 的路径。Windows 上文件夹是 $env:APPDATA\Biomanager（PowerShell）， Linux 上是 ~/.local/share/Biomanager。<you>@<server>：你登录服务器的方式， 例如 ubuntu@biomanager。

    你应该看到：每个文件都复制到 100%。

    如果不是：uploads: No such file or directory：桌面版没有上传过文件。 跳过第二行，以及第 4 步的第二行。

  2. 在服务器上试运行一次导入。它什么都不会改。

    cd /opt/biomanager/Biomanager/deploy
docker compose up -d db
docker compose run --rm --no-deps -v /tmp/lab.db:/import/lab.db:ro app \
  sh -c 'python scripts/migrate-to-postgres.py --dry-run /import/lab.db "$DATABASE_URL"'

    你应该看到：copied : … rows in … tables, row counts verified 和 dry run : rolled back, nothing kept。

    如果不是：列出了 PostgreSQL 不接受的值：在桌面版里改好这些记录，然后重做第 1 步。

  3. 正式导入。

    docker compose run --rm --no-deps -v /tmp/lab.db:/import/lab.db:ro app \
  sh -c 'python scripts/migrate-to-postgres.py /import/lab.db "$DATABASE_URL"'

    你应该看到：copied : … row counts verified，没有 dry run 那一行。

    如果不是：The copy failed and was rolled back：服务器的数据库不是空的 （BioManager 之前启动过）。请到 GitHub 提问。

  4. 启动 BioManager，把上传的文件复制进去。

    docker compose up -d --build
docker compose cp /tmp/lab-uploads/. app:/data/uploads/

    你应该看到：四个服务都显示 Started，然后是 Successfully copied。

完成标志：用桌面版的账号登录 https://<your-domain>，能看到你的记录。 然后做你那种方式里的打开告警一步。

同样的步骤也能用实验室电脑上的副本重建丢失的服务器：改用它 lab-copies/…/db 文件夹里最新的 .db，以及它的 uploads 文件夹。

其他方式

Cloudflare Tunnel
和 E 一样是普通网址，但不开放任何端口：服务器上的 cloudflared 主动连接 Cloudflare， Cloudflare Access 还可以要求先用实验室邮箱登录。我们没有做成现成方案；AI 指南里有说明。
不用 Docker
它是运行在 PostgreSQL 上的 Python 网页应用（gunicorn），前面接任何 HTTPS 代理即可：见 deploy/README.md 的 Without Docker。用 Docker 的话，备份、更新和恢复都只要一条命令。

第三部分

运行之后

运行之后

每一项都链接到运维手册（runbook）里对应的清单；安装包里也有这份手册：deploy/RUNBOOK.md。 系统安全补丁每晚自动安装，容器每周日刷新。

  • 设置实验室：管理员第一次登录时，会问实验室要管理哪些内容（用户指南）。
  • 记下各项信息在哪里，保存在服务器以外的地方： Where everything is。
  • 打开异地备份（Backblaze B2，这个用量免费）：先建好存储桶， 再运行 sudo /opt/biomanager/Biomanager/deploy/host/offsite-setup.sh。
  • 收到告警： 每种告警的含义和处理。
  • 有人加入：把服务器共享给他（Tailscale），在设置 → 管理用户里批准。手机：用 Android 应用， 或在 iPhone 的 Safari 里点分享 → 添加到主屏幕。 Someone joins。
  • 有人离开： Someone leaves。
  • 升级到新版本： Updating the app （出问题时）。
  • 恢复一份备份： Restore a backup。
  • 网站打不开： The site is down。
  • 服务器丢失，或要换一台服务器： The server is lost、 Moving to another server。
  • 管理员登录不了： An admin is locked out。
  • 让访客从互联网进来待几天，不用 Tailscale（方式 D）：在访客里生成通行码，然后运行 sudo host/internet-access.sh on；访客打开 https://<your-domain>:8443/guest。 Letting a guest in、 用户指南。
  • 用 Google、Microsoft 或学校账号登录：在服务商那里登记服务器，把客户端 ID 和密钥写进 .env（BIOMANAGER_GOOGLE_*、BIOMANAGER_MICROSOFT_*，OpenID Connect 用 BIOMANAGER_OIDC_*，只支持 SAML 的大学用 BIOMANAGER_CILOGON_*），然后运行 docker compose up -d。 Signing in with Google or Microsoft。

保护数据安全

多份相互独立的副本，所以任何单一故障（服务器被删、硬盘损坏、笔记本被偷、一次有问题的更新）都不会让实验室的记录丢失。

1 · 每晚服务器备份数据库和上传的文件，检查每份备份都能读取，保留最近 30 份。所有服务器都自动进行。
2 · 每周把最新的备份恢复到一个临时数据库里并检查。自动进行。
3 · 异地加密副本存放在云存储里，按 30 天、12 周和 24 个月保留；打开存储桶的 Object Lock 后， 即使有人控制了服务器也删不掉。Backblaze B2 的前 10 GB 免费。 sudo /opt/biomanager/Biomanager/deploy/host/offsite-setup.sh。
4 · 实验室电脑上桌面版可以保留整个实验室的一份副本：在服务器上，设置 → 实验室副本：保存在你们的电脑上 → 生成密钥；在桌面版里，设置 → 保留实验室服务器的副本，填入地址和密钥。桌面版打开期间每天拉取一份新副本， 保留最近 14 份。管理员的 Mac 还可以拉取服务器每晚的备份：deploy/mac/install.sh （方法）。
5 · 每个人每个表格的导出可以导出 CSV；设置 → 导出我的数据下载你自己的记录和实验记录本页面。
6 · 撤销与历史每次批量修改都可以在批量操作里撤销；审计日志显示每一次编辑、是谁改的，以及改之前是什么。

恢复绝不会删掉被替换的数据： Restore a backup。

常见问题

Oracle 的免费服务器真的免费吗？
Always Free 资源不收费；绑卡是为了验证身份。免费账号的服务器如果看起来闲置一周，Oracle 可能会把它停掉： 重新启动即可，数据不会丢；或者升级为按量付费（方式 D 第 20 步），就不会再被停掉。
Tailscale 用来传实验室数据安全吗？
Tailscale 用 WireGuard 加密直接连接各台设备，它自己看不到传输的内容。不在你 tailnet 里的人根本看不到这台服务器。
服务器需要多大？
2 个 CPU 核心、2 GB 内存、20 GB 硬盘。一个有几万只动物的实验室，数据库也远不到 1 GB。
几个实验室能共用一台服务器吗？
可以每个实验室运行一个 BioManager（各用自己的文件夹和域名），也可以整个动物平台共用一个，每个实验室保留自己的数据库。
有一步没成功，谁能帮忙？
提交一个 issue， 写明你用的方式、第几步，以及它输出了什么。
