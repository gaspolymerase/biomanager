How to…

Restore a backup

Put the desktop app's lab back as it was, from your own backup or from the copy BioManager kept before an update.

Whoever uses that computerDesktop app
  1. Quit BioManager.
  2. Open its data folder: ~/Library/Application Support/Biomanager/ on a Mac, %APPDATA%\Biomanager\ on Windows, ~/.local/share/Biomanager/ on Linux. The lab's database is data/biomanager.db.
  3. Move data/biomanager.db somewhere safe, rather than deleting it.
  4. Put the backup in its place, named biomanager.db.From your Time Machine or File History copy of the folder; or one of the copies BioManager made before a new version changed the database, data/backups/before-upgrade-….db (the last ten are kept). Files added to records and pages are in the uploads folder; put it back from the same backup too.
  5. Open BioManager. To undo an update, open it with the version you had before.

BioManager opens the lab as it was when that backup was made.

Newer changes aren't in a backupEverything entered since the backup was made is not in it. Keep the file you moved aside until you are sure.

On a lab server

A server backs up every night and restores the newest backup every week to prove it works. Restoring is one command, run by whoever looks after the server, and never deletes what it replaces: see deploy/RUNBOOK.md in the server bundle and Keeping the data safe. For a mistake in a bulk change, More → Batch history → Undo is enough.

Troubleshooting

BioManager won't start: the lab's database is an empty file

The file is 0 bytes, so its records are not in it. Put back a backup as above, or delete the empty file to start a new lab.
