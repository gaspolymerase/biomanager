## BioManager 2.13.3

### Fixed

- **The notebook's sidebar comes back.** After **Hide the sidebar**, the small button that shows it again on the notebook's home, a topic, **Recipes** or another library did nothing when clicked: the title row above the page lay over it and took the click. It now opens the sidebar again. **Ctrl+\\** (**⌘\\** on a Mac) did and still does the same. ([#168](https://github.com/gaspolymerase/biomanager/issues/168))
  - **记录本的侧栏又能打开了。** 点 **隐藏侧栏** 之后，记录本首页、主题、**配方** 等页面上那个用来重新显示侧栏的小按钮点了没反应：页面上方的标题栏盖在它上面，接走了点击。现在点它会重新打开侧栏。**Ctrl+\\**（Mac 上 **⌘\\**）一直都可以，现在也照样可以。([#168](https://github.com/gaspolymerase/biomanager/issues/168))
- **Settings opens at once in a lab with large imports.** Opening **Settings** checked, for each of the latest bulk changes in **History**, whether any of its records had been changed since, one record at a time. After a lab imported a few thousand primers or references, that took 10–20 seconds every time Settings opened, and **Batch history** was as slow. It is now one check per bulk change and takes a fraction of a second. What **Undo** allows is unchanged. ([#166](https://github.com/gaspolymerase/biomanager/issues/166))
  - **导入大量数据后，设置也能马上打开。** 打开 **设置** 时，会对 **历史** 里最近的每一次批量操作逐条检查它的记录之后有没有被改过。实验室导入几千条引物或参考文献后，每次打开设置都要 10–20 秒，**批量操作记录** 也一样慢。现在每次批量操作只检查一次，不到一秒就能打开。**撤销** 能做什么没有变化。([#166](https://github.com/gaspolymerase/biomanager/issues/166))

### Updating

- **Lab server on 1.2.6 or later**: **Settings → Version → Update now** (before 1.7.5, **Settings → Devices & copies → Updates**). It backs up first.
- **Desktop app**: *Install and Restart* when it offers 2.13.3, or download it below. Your data is kept outside the app.
- **Lab server on an earlier version**, by hand:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.
  4. Run `sudo host/install.sh`, which sets up **Update now** for next time.

  The database upgrades itself on start, adding one index to the change log; no table changes, and earlier releases' databases were checked to upgrade with nothing lost. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
