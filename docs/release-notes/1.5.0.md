## BioManager 1.5.0

### Works differently

- **A mouse cage's purpose says what it is for, and only that.**
  - **Breeding** is a mating cage, mating now. It is the only cage with **Litter born**, **Genotyping** and **Wean**; a Breeder cage no longer has them.
  - **Breeder** is the lab's breeding stock, the mice kept to be bred. Each person keeps part of it, so a Breeder cage is shared with the lab unless its owner makes it personal. The **Breeders** tab lists only these cages, for anyone to **Pick** from to set up a mating.
  - **Experiment**: mice in an experiment.
  - There is no **Stock** and no **Retired** any more. A cage is **Active** while it holds living mice. **Retire** takes empty cages out of their racks and clears their purpose.
- **The buttons above the cages** (table and cards) are **All**, **Active**, then one for each purpose. The second **Breeding** and **Mine** buttons are gone; **My colony** at the top still shows your own.
- **Your lab's own purposes.** An admin adds or removes them under **Configure → Cage purposes**, or on the **Dropdowns** tab (the same list), and each one gets its button above the cages.
- In Chinese, Breeder is 种鼠笼 and the Breeders tab is 种鼠, so they no longer read like the mating cage.

### Updating

- **Desktop app**: *Install and Restart* when it offers 1.5.0, or download it below. Your data is kept outside the app, and a copy is taken before the database is upgraded.
- **Lab server on 1.2.6 or later**: **Settings → Devices & copies → Updates → Update now**. It backs up first.
- **Lab server on an earlier version**, by hand:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.
  4. Run `sudo host/install.sh`, which sets up **Update now** for next time.

  The database upgrades itself on start:
  - **Stock** cages become **Breeder** cages, shared with the lab (one shared with a project group stays with it).
  - "Exp" and "Experiments" are written **Experiment**.
  - Retired cages lose their purpose.
  - The purpose list loses Stock and Retired and gains any of Breeder, Breeding and Experiment it lacked.

  Cages that were Breeder and are mating now need their purpose set to **Breeding** to show the litter buttons. Every earlier release's database was checked to upgrade with nothing lost. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
