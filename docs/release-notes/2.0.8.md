## BioManager 2.0.8

### New

- **Two cages can be recorded at one rack position.** A new cage is often set up in a position before the cage there is ended, so the cage's form, the sheet, an import or an assistant's proposal now puts a cage in a position another cage holds instead of refusing, and says which cage with living mice is there already. The **Rack grid** shows the cage put there last (one with living mice before an empty one) and marks the position with **!** while two or more there have living mice. Hover over or tap the **!** to list every cage in that position and open one to move it or end it. Empty and ended cages don't count. Dragging a cage onto a position still swaps it with the cage shown there. Home's **Freezer** layout shows the same cage and **!**.
  - **一个笼架位置上可以记录两个笼。** 新笼常常在原来那个笼结束之前就放进了同一个位置，所以现在在笼的表单、表格、导入或助手的提议里把笼放到已有笼的位置时，会照常放进去而不再拒绝，并说明那里已经有哪个有活鼠的笼。**笼架视图** 显示最后放进去的那个笼（有活鼠的优先于空笼）；那里有两个或更多有活鼠的笼时，位置上标一个 **!**。把鼠标移到 **!** 上或点一下，会列出这个位置上的所有笼，打开其中一个就能移走或结束它。空笼和已结束的笼不算。把笼拖到一个位置上，仍然是和那里显示的笼交换。首页的 **俯视** 布局也显示同一个笼和 **!**。

### Changed

- **Numbers sort as numbers in every list.** Cage, tank, litter and other IDs used to come out 1, 10, 101, 2 (the rack's **Unplaced** tray showed it); now they read 1, 2, 10, 101, with A2 before A10 and C-99 before C-104. So do strain and line names, racks, boxes and freezers, a sheet sorted by a column heading, and the cage list on a phone.
  - **所有列表里的编号都按数字大小排序。** 笼、鱼缸、窝等编号以前排成 1、10、101、2（笼架的 **未放置** 栏里就能看到）；现在是 1、2、10、101，A2 在 A10 前面，C-99 在 C-104 前面。品系和品系系名、笼架、盒子和冰箱、点列标题排序的表格，以及手机上的笼列表也一样。
- **Proposed changes are easier to read.** Each change is one line with its database's icon, and a chip on the right says what it came from: what you said, or the photo and the line it read. The quote is in the chip's tooltip and under **Show each change**.
  - **修改提议更容易看了。** 每项修改占一行，带有所属数据库的图标，右边的标签说明它来自哪里：你说的话，或照片及读到的那一行。原话在标签的提示里，也在 **查看每处修改** 下面。

### Updating

- **Desktop app**: *Install and Restart* when it offers 2.0.8, or download it below. Your data is kept outside the app.
- **Lab server on 1.2.6 or later**: **Settings → Version → Update now** (before 1.7.5, **Settings → Devices & copies → Updates**). It backs up first.
- **Lab server on an earlier version**, by hand:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.
  4. Run `sudo host/install.sh`, which sets up **Update now** for next time.

  The database upgrades itself on start: a rack position may now hold more than one cage, and each cage records when it was put in its position (cages placed before count from when they were made). Nothing already there changes, and every earlier release's database was checked to upgrade with nothing lost. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
