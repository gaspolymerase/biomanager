## BioManager 1.2.6

### New

- **A lab server tells its admins when a new BioManager is out.** Once a day the server asks GitHub for the latest release, sending only its own version. When there is a newer one, each admin gets a notification, and **Settings → Devices & copies → Updates** shows what's new with a link to the release notes. Turn the daily look off there with **Check for new versions every day**, or for the whole server with `BIOMANAGER_UPDATE_CHECK=0` in `.env`.
- **Update now**, in the same place, updates the lab's server in one go: a backup first, then the new version (checked against the checksum GitHub publishes), installed and restarted. BioManager is away for a minute or two, and the page follows each step and comes back on the new version. The phone apps open the server, so they follow it; the desktop app keeps updating itself as before.
  - It installs only BioManager's newest release, and only when it is newer than the one running.
  - It needs the server's helpers installed once with `sudo host/install.sh`; the pane says so when they aren't. Every way of setting up a server runs it already.

### Updating

- **Desktop app**: *Install and Restart* when it offers 1.2.6, or download it below. Your data is kept outside the app.
- **Lab server**, this once by hand (from now on, **Update now** does it):
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.
  4. Run `sudo host/install.sh`, which sets up the updater behind **Update now** (it is safe to run again).

  Nothing in the database changes from 1.2.5. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
