## BioManager 2.13.4

### New

- **Hovering a sample's mouse ID shows the mouse.** In **Samples**, rest the pointer on the mouse ID in **Source**: a card shows its sex, age, genotype, status, owner, cage and **Custom tag**, and the notebook pages that name it. Before, only the arrow after the ID showed it. The card is of the mouse typed there now, in the sheet and in a sample's own window. ([#178](https://github.com/gaspolymerase/biomanager/pull/178))
  - **鼠标停在样本的小鼠编号上，就能看到这只小鼠。** 在 **样本** 里，把鼠标停在 **来源** 的小鼠编号上，会弹出一张卡片，显示它的性别、年龄、基因型、状态、负责人、笼位和 **自定义标识**，以及提到它的记录本页面。以前只有停在编号后面的箭头上才会显示。卡片显示的是框里现在填的那只，表格里和样本自己的编辑窗口里都一样。([#178](https://github.com/gaspolymerase/biomanager/pull/178))

### Fixed

- **A sample's mouse ID opens one menu, not two.** Clicking the mouse ID in a sample's **Source** opened the app's list of IDs and, in the Mac app and Safari, a small menu of the browser's over it. Now only the app's opens. It lists the colony's first 200 IDs, and typing narrows them: typing 706 no longer jumps back to 1–200 at 70, which is a mouse too. In a sample's own window, the ID box suggests IDs again. ([#178](https://github.com/gaspolymerase/biomanager/pull/178))
  - **样本的小鼠编号只弹出一个下拉框。** 在样本的 **来源** 里点小鼠编号，会弹出 app 的编号列表，而在 Mac 应用和 Safari 里，上面还会再叠一个浏览器自带的小下拉框。现在只弹出 app 的那个。它列出鼠群的前 200 个编号，打字可以缩小范围：输入 706 时，打到 70 不会再跳回 1–200（70 本身也是一只小鼠）。样本自己的编辑窗口里，编号框又会给出编号建议了。([#178](https://github.com/gaspolymerase/biomanager/pull/178))

### Updating

- **Lab server on 1.2.6 or later**: **Settings → Version → Update now** (before 1.7.5, **Settings → Devices & copies → Updates**). It backs up first.
- **Desktop app**: *Install and Restart* when it offers 2.13.4, or download it below. Your data is kept outside the app.
- **Lab server on an earlier version**, by hand:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.
  4. Run `sudo host/install.sh`, which sets up **Update now** for next time.

  Nothing in the database changes. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
