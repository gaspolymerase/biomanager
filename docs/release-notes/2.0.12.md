## BioManager 2.0.12

### Works differently

- **A long cage sheet comes a page at a time.** As the mice, litters and inventories do, a **Cages** sheet of more than 500 cages now opens with its first page, and each other page comes as you turn to it. Search, sorting, the buttons above the sheet, its count, **Export** and **Print** still go by every cage, and **Open all** / **Close all** still open or fold every one. In a large lab the cages open in about 3 seconds instead of 7½. **Cards** now loads the cages when you switch to it, a few seconds for a thousand or more.
  - **很长的笼表格分页载入。** 和小鼠、窝、库存表一样，超过 500 个笼的 **笼** 表格打开时只有第一页，翻到其他页时再载入那一页。搜索、排序、表格上方的按钮、计数、**导出** 和 **打印** 仍按全部笼来算，**全部展开** / **全部收起** 也仍对每个笼生效。在一个大实验室里，笼表格从 7.5 秒缩短到约 3 秒。**卡片** 视图改为切换过去时才载入笼，上千个笼要几秒钟。
- **A long litter sheet opens about three times sooner.** Its first page is drawn and the other litters are sent as they are, not drawn and then set aside: in a large lab the **Litters** open in about 3 seconds instead of 9.
  - **很长的窝表格打开快约三倍。** 只画出第一页，其他窝不再先画出来再收起：在一个大实验室里，**窝** 表格从 9 秒缩短到约 3 秒。
- **The Mice tab asks the server for less.** It reads only the mice the chosen view (**My colony**, **My groups**, **Shared**) can list, not every mouse in the lab and then picks: in a large lab the server answers in about half the time.
  - **小鼠表格向服务器要的数据更少。** 只读取当前视图（**我的鼠群**、**我的项目组**、**共享**）能列出的小鼠，而不是先读出实验室的所有小鼠再挑选：在一个大实验室里，服务器的应答时间约减半。

### Fixed

- **A cage's purpose shows whatever its case.** A cage whose purpose was written in capitals (BREEDER, from an import) showed "–" in its **Purpose** menu; it now shows **Breeder**.
  - **笼的用途不论大小写都能显示。** 用途写成大写的笼（例如导入时的 BREEDER）在 **用途** 菜单里显示为“–”；现在显示为 **种鼠笼**。

### Updating

- **Lab server on 1.2.6 or later**: **Settings → Version → Update now** (before 1.7.5, **Settings → Devices & copies → Updates**). It backs up first. This is the update that matters for this version: the pages come from the server, so a desktop app or phone joined to a lab's server opens cages and litters faster once the server is on 2.0.12.
- **Desktop app**: *Install and Restart* when it offers 2.0.12, or download it below. Your data is kept outside the app.
- **Lab server on an earlier version**, by hand:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.
  4. Run `sudo host/install.sh`, which sets up **Update now** for next time.

  This version changes nothing in the database's tables. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
