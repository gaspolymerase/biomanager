## BioManager 1.5.3

### Fixed

- **On a Mac, Open your lab finds a lab server at an https address.** The desktop app said *No BioManager answered* at an address that was working, such as a Tailscale one: it could not check any https address's certificate, because it looked for the certificates it trusts in a folder only the computer that built it had. It now uses the list it carries. Anything else the Mac app asks of an https address, such as checking for updates, had the same trouble and is mended with it.
  - 在 Mac 上，“打开你的实验室”现在能找到 https 地址的实验室服务器了；之前即使地址可用，也会说那里没有 BioManager 应答。

### Updating

- **Desktop app**: download it below. A Mac app on 1.5.2 or earlier may not offer *Install and Restart* for this version (the same fault); once on 1.5.3 it offers updates again. Your data is kept outside the app.
- **Lab server on 1.2.6 or later**: **Settings → Devices & copies → Updates → Update now**. It backs up first.
- **Lab server on an earlier version**, by hand:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.
  4. Run `sudo host/install.sh`, which sets up **Update now** for next time.

  Nothing on a lab server changes from 1.5.2, and nothing in the database. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
