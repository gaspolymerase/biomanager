## BioManager 2.0.14

### Works differently

- **The colony's sheets come from the server much sooner.** In a large lab (100,000 mice), the server now answers the **Mice** tab in 0.17 seconds instead of 0.49, **Litters** in 0.4 instead of 2.4, **Cages** in 0.5 instead of 1.15 and **Breeders** in 0.43 instead of 1.07. It reads only what each sheet shows and draws only its first page, and the database looks mice and litters up by the dates and owners the sheets ask for. Nothing looks different.
  - **鼠群的表格从服务器来得快得多。** 在一个大实验室（10 万只小鼠）里，服务器应答 **小鼠** 表格的时间从 0.49 秒降到 0.17 秒，**窝** 从 2.4 秒降到 0.4 秒，**笼** 从 1.15 秒降到 0.5 秒，**种鼠** 从 1.07 秒降到 0.43 秒。服务器只读取每个表格要显示的内容、只画第一页，数据库也能按表格要的日期和负责人直接查到小鼠和窝。外观没有任何变化。
- **The zebrafish Tanks sheet opens with its first page.** As the mouse sheets do, it brings each other page as you turn to it, and search, sort and the counts still go over every tank: in a large lab (3,337 tanks) it comes in half a second instead of 4.6. The **Fish** tab comes in 0.7 seconds instead of 1.9.
  - **斑马鱼的鱼缸表格打开时只有第一页。** 和小鼠表格一样，翻到其他页时再载入，搜索、排序和计数仍然覆盖所有鱼缸：在一个大实验室（3,337 个鱼缸）里，0.5 秒就来，以前要 4.6 秒。**鱼** 表格从 1.9 秒降到 0.7 秒。
- **Inventories come about twice as fast.** A **Samples** or **Reagents** sheet of 20,000 entries comes in 0.7 seconds instead of 1.4 to 1.9. A sample's source box suggests the colony's IDs the first time you type in it, rather than every mouse number coming with the page.
  - **库存表格快约一倍。** 2 万条的 **样本** 或 **试剂** 表格 0.7 秒就来，以前要 1.4 到 1.9 秒。样本来源的编号框在第一次输入时才给出该群体的编号建议，不再让每个小鼠编号都随页面一起发过来。
- **The Cages tab's Rack grid loads its cages when you switch to it**, as an inventory's box grid does.
  - **笼表格的“笼架网格”切换过去时才载入笼**，和库存的盒子网格一样。

### Updating

- **Lab server on 1.2.6 or later**: **Settings → Version → Update now** (before 1.7.5, **Settings → Devices & copies → Updates**). It backs up first. The pages come from the server, so a desktop app or phone joined to a lab's server gets the faster sheets once the server is on 2.0.14.
- **Desktop app**: *Install and Restart* when it offers 2.0.14, or download it below. Your data is kept outside the app.
- **Lab server on an earlier version**, by hand:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.
  4. Run `sudo host/install.sh`, which sets up **Update now** for next time.

  The database upgrades itself on start, adding indexes for the colony's sheets; no table changes, and every earlier release's database was checked to upgrade with nothing lost. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
