## BioManager 2.12.0

### New

- **Samples numbered by type.** Give each sample type a prefix, and a new sample left without a Sample ID is named after it, each type counting on its own: tissue T1, T2, T3…, blood BL1, BL2… It works however the sample is added: **New**, **Add many**, an import from Excel, an experiment's samples or an AI assistant's proposal, and the **New** dialog shows the name it will get (*Left unnamed, they are named T3–T5.*). A Sample ID you type is kept, and the count goes on from it (type T41 and the next is T42); a deleted sample's name is never given again, since its tube may still say it. Set or change a prefix in **Configure**, under *Type choices* (the new **Prefix** beside each type), or with **+** when you add a type. The **#** column is still the sample's number in the whole database. A lab that already named its tissue B1, B2… gives tissue the prefix B, and the next tissue sample is one past the highest B number.
  - **样本按类型编号。** 给每种样本类型填一个前缀，新样本不填样本编号时就按它命名，每种类型单独计数：组织 T1、T2、T3……，血液 BL1、BL2……。无论样本怎么添加都一样：**新增**、**批量添加**、从 Excel 导入、实验里的样本，或 AI 助手的提议；**新增** 对话框会显示它将得到的编号（*不填名称时，依次命名为 T3–T5。*）。自己填的样本编号会保留，之后从它继续往下数（填了 T41，下一个就是 T42）；删掉的样本编号不会再给出去，因为管子上可能还写着它。在 **配置** 的 *类型选项* 里（每种类型旁边新加的 **前缀**），或用 **+** 添加类型时，设置或修改前缀。**#** 列仍是样本在整个样本库里的序号。已经把组织命名为 B1、B2……的实验室，给组织填前缀 B，下一个组织样本就是现有最大的 B 编号加一。
- **A new Samples asks which types the lab keeps.** Instead of opening with nine type tabs, a Samples database you add lists the usual types, each with a suggested prefix: tick the ones you need, change any prefix, add your own (plasma, slides…) and press **Use these types**. **+** adds another type later.
  - **新建的样本库会先问实验室保存哪些类型。** 新添加的样本库不再一开始就有九个类型标签页，而是列出常用类型和建议的前缀：勾选需要的，改成自己的前缀，再加上实验室自己的类型（血浆、切片……），然后点 **使用这些类型**。之后可以用 **+** 再添加类型。

### Works differently

- **Your Samples keeps its types and names.** Nothing is numbered until you give a type a prefix.
  - **已有的样本库保留原来的类型和编号。** 只有给某个类型填了前缀，它才开始自动编号。

### Updating

- **Lab server on 1.2.6 or later**: **Settings → Version → Update now** (before 1.7.5, **Settings → Devices & copies → Updates**). It backs up first.
- **Desktop app**: *Install and Restart* when it offers 2.12.0, or download it below. Your data is kept outside the app.
- **Lab server on an earlier version**, by hand:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.
  4. Run `sudo host/install.sh`, which sets up **Update now** for next time.

  Nothing in the database changes. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
