## BioManager 2.0.5

### Works differently

- **Sheets of a few hundred rows open faster in Chrome, Edge and the Windows app.** These browsers read every box on a page as it opens, including the rows you can't see yet. Since 2.0.0 a sheet of over 1,000 rows has kept its unseen rows off the page until you turn to them. Now a sheet of over 300 rows does the same. A mouse sheet of about 950 living mice opens in about 5 seconds instead of 20, and a fish sheet of 500 in 3 seconds instead of 5 or 6. Sheets under 300 rows are unchanged. Search, sorting, the chips, the count, **Export** and **Print** still cover every row, and editing works as before. Safari and the Mac app never had this delay.
  - **几百行的表格在 Chrome、Edge 和 Windows 版里打开更快。** 这些浏览器打开页面时会读一遍页面上的每个输入框，连还看不到的行也一样。从 2.0.0 起，超过 1,000 行的表格会先把还没看到的行放在页面外，翻到时再放回来；现在超过 300 行的表格也这样做。约 950 只活鼠的小鼠表从约 20 秒缩短到约 5 秒，500 条的斑马鱼表从 5～6 秒缩短到 3 秒。300 行以下的表格不变。搜索、排序、筛选按钮、计数、**导出** 和 **打印** 仍覆盖全部行，编辑也和以前一样。Safari 和 Mac 版从来没有这个延迟。

### Updating

- **Lab server on 1.2.6 or later**: **Settings → Version → Update now** (before 1.7.5, **Settings → Devices & copies → Updates**). It backs up first. This is the update that matters for this version: the pages come from the server, so a desktop app joined to a lab's server opens sheets faster once the server is on 2.0.5.
- **Desktop app**: *Install and Restart* when it offers 2.0.5, or download it below. Your data is kept outside the app.
- **Lab server on an earlier version**, by hand:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.
  4. Run `sudo host/install.sh`, which sets up **Update now** for next time.

  This version changes nothing in the database's tables. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
