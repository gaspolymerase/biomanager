## BioManager 1.2.4

### New

- **A lab server can run on a NAS**, such as one running fnOS (飞牛) ([#48](https://github.com/gaspolymerase/biomanager/issues/48)).
  - A NAS keeps its own web pages on ports 80 and 443. BioManager now checks before it first starts, and when those ports are taken it uses free ones beside them, such as 4443: its address then carries the port, like `https://nas.local:4443`, and the NAS's own pages carry on as before.
  - By hand, run `host/ports.sh` after writing `.env` and before the first `docker compose up -d`; the desktop app's server set-up does it for you. The website's [server page](https://biomanager.org/server.html#lan) says how, route B.
- **Set up a lab server** in the desktop app can sign in with a password instead of an SSH key: in **SSH key**, choose **No key: sign in with a password**.
  - When the account needs a password for `sudo`, as a NAS's admin account does, the sign-in password is tried first, and you are asked for another only if that doesn't work.
  - Passwords are used for that one set-up and never saved, and the set-up's log never shows them.

### Updating

- **Desktop app**: *Install and Restart* when it offers 1.2.4, or download it below. Your data is kept outside the app.
- **Lab server**:
  1. Take a fresh backup (`docker compose exec backup backup.sh`).
  2. Unpack the new `biomanager-server.tar.gz` over the old folder. Your `.env`, backups and certificates are kept.
  3. Run `host/load-image.sh`, then `docker compose up -d --build`.

  A running server stays on ports 80 and 443: there is nothing to change. Nothing in the database changes from 1.2.3. Details are under *Updating the app* in the runbook (`deploy/RUNBOOK.md` in the bundle).
